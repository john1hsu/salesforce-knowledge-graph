# Scheduling Console

The **Scheduling Console** is the newer dispatcher workspace in Field Service (now branded Agentforce Field Service and Operations). Salesforce positions it as a control center for dispatchers built on Lightning Web Components, using GraphQL, server-side filtering and lazy loading so that it stays responsive with thousands of service appointments and resources.[^s1] It is a Field Service managed package feature available in Lightning Experience, with Field Service offered in Enterprise, Unlimited and Developer Editions.[^s2] Help now lists the older workspace separately as the Classic Dispatch Console, so the two coexist in an org.[^s3]

## How it works

The console opens as a tab in the Field Service app and combines three synchronized views.[^s1][^s4]

- **Gantt**: resources as rows and appointments as blocks; dispatchers filter resources, drag appointments, add resource absences and widen the range to several days.[^s1]
- **Service appointment list**: open and scheduled appointments in a standard list view with custom columns and filters; dragging a row onto the Gantt schedules it.[^s1][^s4]
- **Map**: layers for appointment locations, homebases, territory polygons and live traffic, plus planned routes for one or more technicians.[^s5]

The header holds buttons for settings, the map, the Activity Tracker, new resource absences, choosing a scheduling policy and optimizing the schedule; the separators between panes can be resized and the layout is remembered.[^s2] The Gantt resolution defaults to one day and can stretch to long-term views such as two weeks, one month or six months; resource search matches names only, and sorting can use name, type or utilization.[^s2] Utilization is calculated as scheduled work plus travel time divided by working hours minus absence hours.[^s2]

The quick-look unit highlights drag-and-drop scheduling across dual monitors, candidate search that offers a "Why?" explanation generated by AI for each suggested slot, hover popovers on tiles, and org-wide global search that returns a temporary list of up to 50 records.[^s4] Enhanced Live Updates are on by default, keeping the schedule current without manual refreshes.[^s2]

## Setup and configuration

Enabling Agentforce Field Service through Salesforce Go turns the console on; the Migrate to the Scheduling Console section of Salesforce Go then has a button to give dispatchers access, which creates a permission set for them to be assigned.[^s1] Map features need the Scheduling Console app permissions in the Field Service Dispatcher Permissions permission set, and drawing polygons for bulk actions needs the custom permission `FSL.Polygons - create\update`.[^s5]

Admins tune the console in Setup under **Scheduling Console Settings** (also reachable from Salesforce Go).[^s3] Options cover whether secondary territory members appear on the Gantt, how many idle minutes mark a resource offline, the default scheduling policy, the Gantt snap interval, and the Lightning page used for the appointment side panel.[^s3] Custom actions can launch a Lightning Web Component, a flow, an Apex class or a Visualforce page, grouped under appointments, mass actions, resources, absences or breaks, and can be hidden behind a required custom permission.[^s3]

## Limits and gotchas

- The quick-look unit states that the console is available only with Enhanced Scheduling and Optimization; plan that engine before migrating dispatchers.[^s4]
- The Gantt runs in the service territory's time zone; individual user time zones are not supported.[^s2]
- When the appointment list is not matched to the Gantt's date range, live updates use a default window of 7 days before to 30 days after today.[^s2]
- The Service Appointment Lifecycle tab appears automatically only if lifecycle tracking was enabled before the console was first used; otherwise an admin adds it to the side panel page.[^s2]
- Trailhead says customizations from the Classic Dispatch Console keep working and that Gantt state and user settings carry over, which eases a phased cutover.[^s4]

## Connections

The console is **part of** `kt:field-service` and is an **alternative to** the classic `kt:dispatcher-console`, which remains available.[^s3] It **depends on** `kt:enhanced-scheduling-and-optimization` for availability, on `kt:service-appointments` as the records it lists, maps and schedules, and on `kt:field-service-scheduling-policies`, one of which is set as its default.[^s4][^s3] It is enabled and migrated **via** `kt:salesforce-go`, and its custom actions can be gated with `kt:custom-permissions`.[^s1][^s3]
